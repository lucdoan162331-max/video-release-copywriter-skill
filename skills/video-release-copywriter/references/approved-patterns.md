# 已定稿样例规律

本参考记录从五条最终发布文案中验证过的写法。使用时学习结构和取舍，不机械替换名词。

## 总规律

最终稿的共同点不是统一句式，而是统一的信息路径：

`具体输入或场景 → 产品执行具体动作 → 用户看到具体结果`

发布文案、封面文案、金句文案承担不同任务：

| 类型 | 任务 | 判断标准 |
|---|---|---|
| 发布文案 | 让陌生用户理解视频亮点 | 脱离视频也能看懂发生了什么 |
| 封面文案 | 提取唯一点击理由 | 一眼抓到动作或结果 |
| 金句文案 | 配合口播推动情节 | 每一行都能在视频里找到依据 |

## 样例一：直播巡检

### 发布文案

豆包工作化身直播间巡检员，边看画面、边听话术。实时录屏转成飞书妙记，评分和改进建议写入飞书文档。#豆包工作

### 封面文案

用豆包工作直播巡检

实时录屏，给主播打分

### 金句链路

个人困境 → 让豆包工作巡检 → 检查画面和话术 → 给主播打分。

### 学习点

- 用“化身巡检员”建立角色画面。
- 用“边看、边听、录屏、写入”展示过程。
- 结果落到妙记、评分、飞书文档，不写抽象价值。

## 样例二：表格变系统

### 发布文案

100 多万行数据，怎么从多维表格变成真正能用的系统？交给豆包工作，一句话生成！想改细节，直接选定要改的部分，留下评论 AI 继续改。真正好用的系统，是和豆包工作协作改出来的！

### 封面文案

豆包工作把表格变系统

双击编辑，局部细节轻松改

### 金句链路

数据规模 → 一句指令 → 系统出现 → 选中局部继续编辑。

### 学习点

- 只有“100 多万行”这种能制造感受的数字才前置。
- 不只写生成，还补充可控性和协作修改。
- 问句来自真实难题，不是为了形式强加。

## 样例三：企业数据沉淀

### 发布文案

豆包工作要在企业里真正干活，数据和上下文不能少！飞书多维表格不仅能存数据，还能承载每条数据的状态。把企业数据沉淀好，让豆包工作拿来即用！#豆包工作

### 封面文案

想让豆包工作发挥更大价值

先把企业数据沉淀好

### 金句链路

agent 没有数据一无是处 → 需要组织 context 和上下文 → 先用多维表格沉淀企业数据。

### 学习点

- “拿来即用”比“基于组织上下文产出更高质量结果”具体。
- “沉淀数据”比“数据治理”更接近用户动作。
- 金句保留“agent 没有数据其实一无是处”这种有判断力的原话。
- 不为凑六句加入泛化结论；五个有效节拍也成立。

## 样例四：豆包工作做 PPT

### 发布文案

把你的材料发给豆包工作，它会梳理整套叙事，逐页设计版式、图表和视觉亮点，做出一套审美在线、还能编辑的 PPT！#豆包工作

### 封面文案

豆包工作10分钟交付，一套审美在线可编辑的PPT

### 金句链路

豆包工作做 PPT → 理解材料内容和表达目标 → 组织叙事 → 逐页设计版式、图表和视觉亮点。

### 学习点

- 用“把材料发给”启动动作，比“你只需要交给”更短、更具体。
- 发布文案用一个长而顺的动作链，不连续设问、转折和感叹。
- “10 分钟”作为封面证明点，不必在发布文案里硬说“很快”。
- 封面一行已经表达完整时，不强拆为两行。
- 原口播里的“不是简单套模版”可以留在金句中；发布文案直接正向写执行过程。

## 样例五：智能体小队

### 发布文案

输一个关键词，3 个智能体接力干活！华熙生物一线运营人员在豆包工作里组建智能体小队，科技情报官搜信息、内容策划师做内容、科学审核员二次审核。全程自动交接，交付更高质量的结果！#豆包工作

### 封面文案

在豆包工作召唤智能体小队

做调研出策划生视频，样样行

### 金句链路

输入一个关键词 → 3 个智能体开工 → 情报官搜信息 → 策划师产内容 → 审核员二次审核 → 团队交付结果。

### 学习点

- “输一个关键词”直接写最小输入和结果。
- 加入“华熙生物一线运营人员”，让产品能力变成真实业务案例。
- “召唤”比“组建”更有记忆点，但仍符合智能体小队的画面。
- 角色名称、顺序和交接必须忠于视频。

## 初稿到定稿的典型优化

| 初稿问题 | 定稿处理 |
|---|---|
| 基于组织上下文产出更高质量的结果 | 换成“拿来即用”等可见结果 |
| 数据治理、发挥价值等抽象表达 | 换成“沉淀数据、发给、变成、交接”等动作 |
| 强行用问题制造钩子 | 直接从输入或动作开始 |
| 连续短句造成一顿一顿 | 合并成一条顺畅动作链 |
| 封面固定两行 | 一行足够时保留一行 |
| 金句重新总结视频 | 改为截取原口播并按真实顺序排列 |
| 泛化产品能力 | 加真实人物、客户、数字或产物 |
| 最后一句重复开头 | 结尾落在新结果或直接收住 |

## 金句版面硬约束

金句要直接进入封面模板，因此“5–6 句”必须同时满足行数和字数约束：

- 默认 5 行；第 6 行只留给不可合并的关键情节。
- 一句对应一行，不允许依赖自动折行。
- 5 行版每行 8–16 个等宽字符、总计不超过 75 个；6 行版每行不超过 14 个、总计不超过 78 个。
- 一行只放一个判断或动作，优先保留最有画面的名词、动作和一组关键数字。
- 同时出现“原价、现价、降幅、严重程度”时，保留最直观的价格变化和结论，删掉重复证明。

### 过长案例的压缩方式

以下写法虽然忠于口播，但第三、第五和第六行信息过载，放进金句封面容易折行：

```text
零售价格体系就是生命线
内部压力大的时候，就会有人主动去破价
我用新版飞书 aily，复刻了一个速成版的圣小价
当日实售价跌破控价，就意味着破价了
地道脆骨串从 11 块降到 7 块 9，破价幅度 28.2%，严重破价
以前驯化要一个月，他两三分钟就驯化成这样
```

压缩后保留原意、顺序和关键事实，同时每句天然占一行：

```text
零售价格体系就是生命线
压力一大，就有人主动破价
我用飞书 Aily 做了个圣小价
实售价跌破控价，就算破价
11块降到7块9，严重破价
一个月的驯化，两三分钟搞定
```

学习点：

- “内部压力大的时候”压成“压力一大”，不损失因果。
- 删除“新版、复刻、速成版”等同向修饰，只留产品动作和产物。
- 价格变化已经证明破价程度时，删除 28.2% 这一组重复数字。
- “以前……他……”压成时间反差，保留口语力度。

## 交付前反向检查

读完文案后回答：

1. 用户具体交给产品什么？
2. 产品具体做了哪些动作？
3. 最终出现了什么看得见的结果？
4. 这条和其他产品文案相比，多了什么独有信息？
5. 删除最后一句后是否信息完全不损失？如果是，删掉。
6. 金句是否来自口播，而不是来自作者的产品总结？
7. 每句是否只占一行，逐行及总字数是否都能放进金句封面？

任何一问答不出来，都需要重写。
